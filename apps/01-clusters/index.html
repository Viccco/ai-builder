Axial coding
What this step is, and how to work it

You just labelled 30 bot drafts. This step turns that pile of individual complaints into a small number of named failure modes, which is the thing you can actually hand to an engineering team. The method has a name, axial coding. You read the critiques you wrote, notice the same underlying cause turning up in different words, and give that cause a name.

Only your failures appear here. The passes are left out on purpose, because you are mapping how the product breaks rather than summarising everything it did.

What makes a good category. Name the cause, not the remedy. "Invents facts it cannot know" is a cause. "Add a knowledge check" is a fix, and several different causes can share one fix, so naming by fix collapses things that should stay apart. Each category needs one sentence saying what has to be true for a trace to belong in it, and if you cannot write that sentence the category is not real yet. Aim for three to six.

How it works. You see one failure at a time with everything you need to judge it. Click the category it belongs to, or press its number. Name a new category right there when nothing fits. When everything is sorted you land on the board, where you write the definitions, move things around and star the clearest example of each mode.

Then click Copy for Claude Code and paste it into the chat. Claude Code counts, checks whether a category is doing two jobs, and argues with the definitions that are vague.
