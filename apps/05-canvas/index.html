Eval plan

1. Decision metric

One sentence: what "the answer was good" means here. Then the decision it feeds. If no number would change what anyone does next week, this is a dashboard, not an eval.

2. Golden set

10 to 15 cases you would actually put in front of this product. You write the reference answers. If you cannot write them, you do not yet know what good means.

3. Graders

Split the bar three ways. Anything that can be code should be code, because it is cheaper and never drifts.

4. What this suite cannot see

Name it yourself, before a stakeholder does.

5. The production half

From module 4. Signals in priority order, a sampling policy sized to a real review budget, and the ritual that turns reviewed failures into eval cases.
