The judge prompt

Who the judge is and whose standard it applies. Yours.
What it is given, and what the system could and could not have known when it answered.
One failure mode. If you need the word "and" here, you need a second judge.
What fail means, what pass means, precisely enough that two people would agree. Always ask for a verdict and a one-sentence critique.
Two or three, lifted from your own critiques. This is where the judge gets your taste.

The results file format

Ask Claude Code to write JSON in this shape. Anything extra is ignored.

{
  "round": 1,
  "set": "dev",
  "judge": "asserts what it can't back",
  "results": [
    { "id": 2, "verdict": "fail", "critique": "States a cause as fact." },
    { "id": 4, "verdict": "pass", "critique": "Asks for data instead of asserting." }
  ]
}

The positive class is fail, because finding failures is the job. Precision is how many of the judge's fails were real. Recall is how many of your fails it found.
